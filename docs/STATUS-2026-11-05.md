# Infinite Future Bank — Platform Status (5 November 2026)

What works, what does not, what to fix now, and what to fix later.

**How this was checked:** a read-only audit of the **live** Supabase project
(`nfztdpyygfrpbjbhidxe`, "IFB", production): its tables, security settings, database
functions, storage buckets, deployed edge functions and configured secret *names*.
No customer records were read. It was cross-checked against the code on `main`
(commit `947a22c1`) and against tests from outside, as an anonymous visitor.

## 3. What doesn't work, or works but is unsafe

### 3a. Works, but unsafe (old server code still live: Phase 2)

| Function | Problem | Gateway login check |
|---|---|---|
| `process-withdrawal` | Withdraws **anyone's** balance to an attacker's bank | ❌ off |
| `process-payout` | Same as above, for payouts | ❌ off |
| `ifb-charge-card` | A negative amount moves money from a merchant to the attacker | ❌ off |
| `verify-otp`, `face-auth` | Account takeover (demo OTP bypass; face login by email only) | — |
| `kyc-*` admin functions | The admin login token can be forged | ❌ off |
| `send-email` | Anyone can send email as IFB | — |
| `flutterwave-transfer` | Pays the dollar amount as local currency (for example $10 becomes 10 cedi) | — |
| `confirm-deposit`, `stripe-webhook` | A deposit can be credited twice | — |
| `issue-ifb-card`, `link-external-card`, `process-afr-transfer`, `process-p2p-receipt`, `afr-mint` | Trust the user id or amount sent by the caller | — |

The fixed versions are on `main`. Deploying them changes behaviour for the **old**
app version, so they go live after 1.5.8 reaches Production (section 5).

### 3c. Live database: security findings

| # | Finding | Severity |
|---|---|---|
| D1 | **14 money functions can be run by logged-out visitors**, and several take the user id and amount from the caller with no check. `increment_balance(user, amount)` adds money to any account. `fund_pocket`, `pay_insurance_premium`, `initiate_p2p_withdrawal`, `sl_pay_for_package` and `release_milestone_funds` debit or credit any user. `sl_credit_carrier` and `fund_community_loan` move money for anyone. | 🔴 Critical |
| D2 | **53 tables have row-level security off** and are open to logged-out visitors, for reading and writing. They include `infinite_cards` (**card number, expiry, CVV**), `sl_partner_keys` (**partner API keys**), `standard_withdrawals` (bank details), `balance_corrections`, `stripe_unattributed_deposits`, `ifb_revenue_ledger`, `payroll_employees` (salaries), `loan_requests`, `contact_messages` and `newsletter_subscribers` (personal data). | 🔴 Critical |
| D3 | 2 views expose internal money figures to the public: `ifb_revenue_summary` and `venturex_balance_check`. | 🟠 High |
| D4 | 22 tables have "anyone can write" rules, for example `notifications`, `npo_donations`, `protected_addresses`, `sl_relay_legs` and `deus_market_order_items`. | 🟠 High |
| D5 | 7 storage buckets are **public**: `documents`, `company-docs`, `delivery-proofs`, `avatars`, `company-logos`, `news_images` and `academy-videos`. The first three may hold private documents. | 🟠 High |
| D6 | **8 deployed functions have no source code in the repo**, so nobody can review them: `debug-twilio-config`, `partner-api`, `send-sms`, `send-push`, `daily-risk-aggregator`, `ifb-risk-index`, `michael-daily-briefing` and `venturex-notify-interest`. | 🟠 High |
| D7 | `schema-probe` is deployed and answers anyone with the database structure. | 🟡 Medium |
| D8 | 135 database functions run with admin rights; 80 of them can be run by logged-out visitors, and 55 lack a fixed `search_path`. | 🟡 Medium (review) |
| D9 | 70+ secrets are configured, including AWS, Stripe, Twilio and several AI keys. Some of these leaked through the repo's history. | 🔴 Rotate (owner) |
| D10 | The auth redirect list includes outside sites (`skyhol.com`, `skylink-*.vercel.app`, `michael.worlddisastercenter.org`), so another app shares this backend. | ℹ️ Note: the `sl_*` tables and functions belong to it |

## 4. Fix now (no effect on logged-in app users)

| # | Action | How | Effect on users |
|---|---|---|---|
| N1 | **Lock the open money functions and tables (D1–D3)** | Run `supabase/migrations/20261107_lock_open_objects.sql`, **Part A** | None for logged-in users. Logged-out visitors lose access they should never have had. Public forms still accept submissions. |
| N2 | Delete `debug-twilio-config` and `schema-probe` (D6, D7) | `npx supabase@latest functions delete <name>` | None; no app uses them. |
| N3 | Fix and deploy `delete-account` | Small code change: refuse deletion while the user still has a balance, then deploy | Account deletion starts working, as Google Play requires. |
| N4 | Turn on card payments for Payment Pages | Set `STRIPE_PUBLISHABLE_KEY` (the public `pk_live_…` key) | Merchants can take card payments. |
| N5 | Test 1.5.8 from Internal testing, then **promote it to Production** | Play Console | Users get the fixed, safer app. |
| N6 | Redeploy the web app on Netlify | Netlify dashboard → Deploys → Trigger deploy | The web gets the badges and fixes. |

Part A of N1 was checked against every app in this repo: none of them reads the
locked tables or calls those functions while logged out.
